# AquaTrack – LPU Campus Water Availability Prototype

A simple student-reporting map for a design-thinking prototype. It uses Leaflet + OpenStreetMap and has two operating modes:

- **Local Demo Mode (works immediately):** sample reports are clearly marked as demonstration data; new reports save in this browser only.
- **Optional Shared Mode (Firebase):** if you configure Firebase, student reports are stored in Firestore and automatically appear for other users who open the site.

No sensors, admin panel, machine-learning, or complicated verification system is included. The newest report from the last two hours controls a point's colour. Older points turn grey.

## Important accuracy notes

- The five map pins are reference areas copied from the supplied LPU campus navigator dataset. They are **not confirmed drinking-water dispenser coordinates**. Physically locate and update every pin before using this with students.
- Demo entries are not real interviews or student reports. The first real local report clears the demo entries in that browser. Shared mode displays only actual Firestore reports.
- Green means a student recently reported water as available; it does **not** certify drinking-water safety.
- Timestamps in the interface are formatted in each viewer's device timezone. Shared-mode report creation time is generated by Firebase server time, avoiding reliance on the reporter's device clock.
- Local Demo Mode is not shared between browsers or devices.

## Run locally

1. Extract this ZIP.
2. Open the folder in VS Code.
3. Use the Live Server extension, or run `python -m http.server 8000` in this folder.
4. Open `http://localhost:8000`.
5. Keep internet access on for Leaflet and OpenStreetMap map tiles.

## Optional: enable shared multi-user reports

This is optional. The site remains usable as a local prototype without it.

1. Create a project at https://console.firebase.google.com/.
2. Add a Web App in Project settings and copy its Firebase config.
3. In **Authentication → Sign-in method**, enable **Anonymous**.
4. Create a **Cloud Firestore** database.
5. Open `firebase-config.js` and replace the placeholder values with your project's `apiKey`, `authDomain`, `projectId`, and `appId`.
6. In Firestore **Rules**, paste the contents of `firestore.rules` and publish them.
7. Host the folder using Firebase Hosting, Netlify or another HTTPS static host. Firebase Authentication and Firestore are also usable from localhost for testing.
8. Open the same deployed URL on two devices. Submit a report on one; the other should update automatically.

### Firebase security note

The included rules require anonymous authentication, restrict submissions to the five known point IDs and three status values, and prevent editing/deleting existing reports. This is a student prototype, not a hardened public service. Anonymous users can still submit multiple reports. Before a campus-wide launch, add abuse controls and ask the university/facilities team for approval.

## Files

- `index.html` – page structure and library loading
- `styles.css` – responsive interface
- `app.js` – map, reports, freshness rule and optional Firestore sync
- `firebase-config.js` – optional Firebase web configuration placeholders
- `firestore.rules` – basic Firestore access rules

## Third-party services

The map uses Leaflet and OpenStreetMap tiles. Firebase is only used if configured. Review each service's current terms and quotas before broad deployment.
